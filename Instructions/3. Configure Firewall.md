# Configure Firewall
> Firewall controls network access. Only allows connections on ports you specify.

## Step 1: Configure UFW rules
```bash
# Set default policies
ufw default deny incoming
ufw default allow outgoing

# Allow SSH (port 22)
ufw allow 22/tcp

# Allow HTTP and HTTPS for web traffic
ufw allow 80/tcp
ufw allow 443/tcp

# Block 3000 port
ufw deny 3000/tcp
```
**Explanation:**
- **ufw default deny incoming**: Blocks all incoming connections by default for security
- **ufw default allow outgoing**: Allows outgoing connections so the server can access external services
- **ufw allow 22/tcp**: Allows SSH connections on port 22 for remote access
- **ufw allow 80/tcp**: Allows HTTP web traffic on port 80
- **ufw allow 443/tcp**: Allows HTTPS web traffic on port 443 


## Step 2: Enable Firewall
```bash
ufw enable
```

## Step 3: Verify Firewall Status
```bash
ufw status verbose
```

## Step 4: Try to acchess 3000 port
```bash
http://your_vps_ip:3000
```

## Step 5: Block Docker Container Direct Port Access
Docker containers bypass UFW firewall rules by default. Even though UFW shows ports as blocked, Docker directly exposes container ports to the network, creating a security vulnerability.

The solution: Use the DOCKER-USER iptables chain, which is specifically designed for user-defined firewall rules that Docker respects.

```bash
# Block external access to port 3000 (Dokploy dashboard)
sudo iptables -I DOCKER-USER -p tcp --dport 3000 -j DROP

# Check DOCKER-USER chain rules
sudo iptables -L DOCKER-USER -n -v --line-numbers

# Delete the rule if you no longer need it
sudo iptables -D DOCKER-USER 1
```

## Step 6: Try to access 3000 port
```bash
http://your_vps_ip:3000
```
You will see it can't access.

## Step 7: Persistent iptables rules across reboots
```bash
# Install iptables-persistent
sudo apt install iptables-persistent -y

# Save current iptables rules
sudo netfilter-persistent save
```
