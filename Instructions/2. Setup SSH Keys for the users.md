# Setup SSH Keys for Users
> This guide will help you set up SSH keys for users on your VPS instance and block password login to prevent unauthorized access.

## Step 1: Create SSH directory for users
```bash
mkdir -p /home/rasel/.ssh

chown rasel:rasel /home/rasel/.ssh
chmod 700 /home/rasel/.ssh
```
**Explanation:**
- `chown` ensures the correct user owns the directory, then `chmod 700` ensures only that owner can access it - both commands together create secure SSH key storage. 

## Step 2: Create SSH keys on your local machine
```bash
ssh-keygen -t ed25519 -C "rasel@stacklearner.com"
```
**Explanation:**
- `-t ed25519`: Uses modern, secure encryption algorithm
- `-C "rasel@stacklearner.com"`: Adds a comment to identify the key

## Step 3: Create authorized_keys file and paste the public key into it

```bash
nano /home/rasel/.ssh/authorized_keys

# Set the read and write permissions to the authorized_keys file for user rasel
chown rasel:rasel /home/rasel/.ssh/authorized_keys
chmod 600 /home/rasel/.ssh/authorized_keys
```
**Explanation:**
- `chown` ensures the correct user owns the authorized_keys file, then `chmod 600` ensures only that owner can read and write the file - both commands together create secure SSH key storage.


## Step 4: Secure SSH Configuration
```bash
# Edit SSH config file
sudo nano /etc/ssh/sshd_config

# Add or modify these settings:
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
AllowUsers rasel hmnayem
```
**Explanation:**
- **PermitRootLogin no**: Prevents direct root access via SSH
- **PasswordAuthentication no**: Forces SSH key usage only (disables password login)
- **PubkeyAuthentication yes**: Enables SSH key authentication
- **MaxAuthTries 3**: Limits failed login attempts to prevent brute force attacks
- **AllowUsers rasel hmnayem**: Only allows specified users to SSH in

## Step 5: Verify password authentication is disabled
```bash
# This shows what SSH is actually using (not just what's in config file)
sudo sshd -T | grep passwordauthentication

```

## Step 6: If password authentication is enabled, check for cloud-init override files
```bash
# List additional SSH config files that might override your settings
ls -la /etc/ssh/sshd_config.d/

# Check what's in these files
sudo cat /etc/ssh/sshd_config.d/*.conf
```
**Note:**
Cloud-init creates these override files during VPS initial setup to provide default SSH configuration. These files can override your main sshd_config settings, which is why you need to check and edit them to ensure your security changes take effect. 


## Step 7: Edit cloud-init files to match your settings
```bash
# Edit each cloud-init file
sudo nano /etc/ssh/sshd_config.d/50-cloud-init.conf

# Change to match your security settings:
PasswordAuthentication no

# Verify Again
sudo sshd -T | grep passwordauthentication
```


## Step 8: Before restarting SSH, test access in a new terminal
```bash
ssh rasel@your-vps-ip-address
```

## Step 9: Restart SSH
```bash
# Check available SSH service name
systemctl status sshd
# or
systemctl status ssh

# Restart SSH service (use the one that's active)
sudo systemctl restart sshd
# or for Ubuntu/Debian:
sudo systemctl restart ssh
# or alternative:
sudo service ssh restart
```
**Explanation:**
Different Linux distributions use different SSH service names. Check which service is running on your system first, then restart that specific service.

## Step 10: Login to the VPS using SSH keys
```bash
# If you have a custom key name, specify it with -i
ssh -i ~/.ssh/my_custom_key rasel@your-vps-ip-address

# To keep connection alive for 1 hour
ssh -o ServerAliveInterval=60 -o ServerAliveCountMax=60 -i ~/.ssh/my_custom_key rasel@your-vps-ip-address
```
**Explanation:**
- SSH automatically looks for the default key file (`~/.ssh/id_ed25519`)
- Use `-i` flag if your key has a custom name or location
- The `ServerAliveInterval` options prevent connection timeout during idle periods
